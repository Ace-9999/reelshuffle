SRS: Saved Reels Feed (Chrome Extension)
Nov 15, 2026  ·  @AV
1. Introduction
This document specifies a personal Chrome extension (working title: ReelShuffle) that
loads the user's Instagram saved reels, shuffles them, and plays them in a vertical full-
screen feed with an unsave button that syncs back to Instagram.
1.1 Purpose
Instagram's saved collection is a long, unordered archive that is hard to revisit.
ReelShuffle turns it into a random, scrollable feed so saved reels actually get watched
again.
1.2 Scope
Runs only in the user's own Chrome browser, inside their logged-in Instagram session.
Reads the user's saved reels, plays them in a custom feed, and unsaves them on
request.
Single user, personal use. No backend server, no public hosting, no sharing of content.
1.3 Definitions
Term Meaning

Instagram's Save button

2. Overall description
2.1 Product perspective
A standalone Chrome extension (Manifest V3) that piggybacks on the user's logged-in
Instagram session. A normal website cannot do this job, because browsers block cross-
site calls that carry Instagram cookies. An extension with host permission for
instagram.com can make those calls legitimately from the user's own browser.
2.2 Product functions (summary)
1. Detect that the user is logged in to Instagram.
2. Fetch the full list of saved reels, page by page.
3. Cache the list locally and refresh it on each open.
4. Shuffle the list and play it in a vertical snap-scroll feed.
5. Let the user unsave a reel with one click, synced to Instagram.
2.3 User characteristics
One user: the developer and owner of the Instagram account. Comfortable loading an
unpacked extension in Chrome developer mode. No accounts, onboarding or support
needed.
Term Meaning
Internal endpoints Instagram's undocumented web API calls used by
instagram.com itself

2.4 Operating environment
Desktop Chrome (or a Chromium browser such as Edge or Brave) on Windows,
macOS or Linux.
The user is already logged in to instagram.com in the same browser profile.
Not supported in v1: mobile browsers, Safari, Firefox.
2.5 Assumptions and dependencies
Instagram's internal web endpoints for listing saved posts, resolving a reel's video
URL and unsaving remain reachable with the session cookies. Their exact paths and
response shapes must be confirmed by inspecting the site's network traffic, and they
can change without notice.
Video file URLs returned by Instagram are signed and expire, so they are fetched
fresh when needed.
2.6 Constraints
Must be built on Manifest V3 (service worker, no remotely hosted code).
No backend server and no third-party data storage. Everything stays in the browser.
Request volume must stay low and human-paced to avoid rate limits (see NFR-4).

5. Non-functional requirements
ID Category Requirement
NFR-1 Performance With a warm cache, the first reel starts playing
within 2 seconds of opening the Feed page on a
normal broadband connection.
NFR-2 Performance Swiping to the next reel starts playback within 500
ms when it was pre-loaded.
NFR-3 Scalability Handles at least 2,000 saved reels without
noticeable lag. Only the current reel plus 2
neighbours hold a loaded video element.
NFR-4 Safety / rate limiting Saved-list pages are requested at least 1 to 2
seconds apart, and no more than one video-URL
lookup is in flight at a time. Backs off exponentially
on any 429 or challenge response.
NFR-5 Reliability If Instagram is unreachable, the cached list still
opens and plays whatever videos can load. Failures
never crash the feed.
NFR-6 Security No password, token or cookie value is ever stored,
logged or sent anywhere except back to
instagram.com. The CSRF token is read at call time
only.
NFR-7 Privacy All data stays on the user's device. No analytics,
telemetry or third-party requests.
NFR-8 Compatibility Works on current stable Chrome and Chromium-
based browsers (Manifest V3).
NFR-9 Maintainability All Instagram-specific code (endpoint paths,
headers, response parsing) lives in one module, so
a format change means editing one file.
NFR-10 Usability Controls and gestures match Instagram's reels
behaviour closely enough that no learning is
needed.

6. Data model and architecture
6.1 Components
The Feed page never calls Instagram's API itself. It asks the service worker for anything
that needs the session, and reads the reel list straight from IndexedDB. Video files stream
from Instagram's CDN into the page's video element.

Video URLs are intentionally not stored (FR-20).
6.3 Typical sequence
1. User clicks the toolbar icon, and the Feed page opens and draws from the cache.
2. The page asks the service worker to sync. The worker checks the session, then pages
through the saved list with delays.
3. New and removed reels update IndexedDB. The page picks up the changes and
reshuffles on the next round.
4. As a reel nears the viewport, the page requests a fresh video URL through the worker
and starts playback.
5. User presses Unsave. The worker calls Instagram, the cache entry is deleted, and the
feed moves on, with Undo available for 5 seconds.

7.2 Terms of use
Instagram's terms do not permit automated access to its service by unofficial means, and
the saved list has no official API. This design reduces the exposure: one user, one account,
the user's own logged-in browser, human-paced requests, no stored credentials, no public
distribution and no redistribution of videos. It does not remove the risk, and the account
owner accepts it. If this ever becomes a public product, the design needs to be revisited.
7.3 Out of scope for v1
Mobile and Safari support.
Downloading or exporting videos.
Multiple accounts.
Collections, filters or search by author or caption.
Publishing to the Chrome Web Store.
Any server component.

8.2 Milestones
8.3 Open questions
Should saved photos and carousels be included, or reels only (current default: reels
only)?
Is desktop Chrome enough, or is a phone-friendly version needed later? A phone
would require a different approach.
Pressing Unsave removes the reel from Instagram's saved list (verified in the
Instagram app) and from the feed. Undo within 5 seconds restores it.
A library of at least 500 saved reels loads and scrolls without lag.
Logged out, the page shows the login prompt and makes no further calls.
A simulated 429 or format change stops requests and shows the right message while
the cache stays usable.
No requests go to any host other than Instagram and its video CDN.
